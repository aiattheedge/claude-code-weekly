# The question

Welcome to the first AI at the Edge Research Edition, from Side of My Desk. Today's question: do AI plugins age badly? A plugin is a set of written steps that tells an AI coding tool how to do a job: which helpers to start, what to look for, what to skip. Those steps are written for the models of the day. Then a newer model comes out, and few people check whether the steps still help. So I checked one.

# A natural test

I tested Anthropic's official code-review plugin for Claude Code. Its current steps were added on October 26th. Claude Opus 5.5 came out before that, in September. Claude Fable 5.2 came out after it, on November 9th. So Fable is newer than the plugin. If plugins age badly, the plugin should help less on Fable.

# What I did

I took 15 real code changes from five open-source projects. Human reviewers had already listed the mistakes in them, 53 in all. Each change was reviewed two ways. With the plugin. And without it: I just asked, in one paragraph, review this and report every bug. Two models, two rounds each. That's 120 reviews. And I kept a record of which model answered every single request.

# The headline

Here's the headline. Just asking found about twice as many of the known mistakes. On Opus 5.5, 66 percent, against 31 percent with the plugin. On Fable 5.2, 73 against 32. And that gap is far wider than the uncertainty in a study this size.

# Every change

And it wasn't a few changes pulling the average. On none of the 15 code changes, on either model, did the plugin find more known mistakes than just asking. At best they tied, on two changes per model.

# Every level

The gap shows up at every level of seriousness, from critical mistakes down to low ones.

# Steadiness

The plugin was also less steady. Of the known mistakes a setup found at least once, the plugin found 63 to 65 percent in both rounds. Just asking found 83 to 84 percent both times.

# Cost

Just asking also cost less. On Opus 5.5, 41 cents a review, against 60 cents with the plugin. On Fable 5.2, a dollar fourteen against a dollar seventy-five. The plugin cost about one and a half times as much.

# What the plugin does well

Now, to be fair to the plugin, it does one thing well. It says much less: about two findings a review, against ten or eleven. And more of what it says is right. On Opus 5.5, 53 percent of its findings matched a known mistake, against 21 percent for just asking. On Fable 5.2, 43 against 26. If your team treats every review comment as an interruption, that short list has real value. If you want mistakes caught before the code ships, in this test you did better by just asking.

# Leaders, one: the model you pay for

Three things every engineering leader should know. First, a plugin may not use the model you pay for. This plugin names a model for each of its helpers. When I chose Fable 5.2, the bug hunting and the double-checking still ran on Opus 5.5. That was 43 percent of the plugin's bill. Moving up a model did not get me a newer review.

# Leaders, two: which model answered

Second, your tooling may not tell you which model answered. When a Claude model refuses a request, Claude Code normally sends it to a different model and keeps going. In set-up testing, I used a stand-in service that answered as a different model. My own records caught the switch. Claude Code's summary at the end still named the model I had asked for. So if you compare models on quality or cost, keep a record for every request.

# Leaders, three: a model may ignore the plugin

Third, a model may ignore the plugin anyway. The plugin tells the AI to hand the work to a team of helpers. Fable did that every time. Opus 5.5 skipped the team in 13 of its 30 plugin reviews and worked alone. Those reviews cost 28 cents instead of 85, about a third, and did about as well. The model chose when to skip, so that's a hint, not a fair test.

# Did it age badly?

So, did the plugin age badly? Partly. Its one advantage, more of what it says being right, shrank on the newer model, from about 32 points to about 17. That drop is clear enough that it's probably real. On known mistakes found, the plugin fell about 6 points further behind on Fable, but that could be chance. Both lean the same way. So the idea got some support. It is not settled. And because the plugin sent its checking to the older model, I can't fully tell why.

# The surprise

Now the surprise. The reviews reported 543 things that weren't on the reviewers' list. A second AI checked every one and judged 285 of them real. Counting each mistake once, that's 123 separate mistakes the list doesn't have. The list has 53. A more careful second look at 30 of those judgements agreed with 24, so the true number is probably a little lower. Still, the test set seems to hold fewer than half of the real mistakes in these changes.

# Counting the real extras

Count those real extras as good findings, and the picture changes a little. The plugin's findings were good 81 percent of the time on Opus, and 72 on Fable. Just asking was 63 and 67. So the plugin's edge in being right is real on Opus, and small on Fable. But per review, just asking gave about seven good findings. The plugin gave fewer than two. Just asking found 118 of the 123 new mistakes. The plugin found 24.

# The limits

Please take all of this as a first look. It's small: 15 code changes, one plugin, two models. The test set is public, so the models may have seen it. An AI did the grading, and no person checked it. And I didn't set pass marks ahead of time. It's enough to say the question deserves a bigger test. It's not a verdict on the plugin, or on plugins in general.

# What to do on Monday

So what would I do on Monday? Read your plugins. This one is a single page of instructions, and it picks its own models. Check which model does the work, and keep a record. And test again when the model changes. This whole study cost about 136 dollars.
