Hooks CHANGED · v2.1.314 · OCT 30

Hook rules now cover the Monitor tool

Could Claude slip a risky command past your hook by running it in the background?

Time 10 minLevel intermediateFor plugin authors
What
The Monitor tool runs a command in the background and tells Claude what it prints. A hook can use an if rule, such as Bash(rm *), to run only for some commands. Before 2.1.314, hooks that match Bash did not run on commands the Monitor tool started. Now they do. Also, an if rule such as Monitor(tail *) now matches Monitor commands the same way Bash(tail *) matches Bash commands.
Why
One rule now guards both tools. Note that these hooks can block or ask on Monitor commands, but they cannot approve or change them.
Needs
Version 2.1.314 or later.
Save in .claude/settings.json (the docs' example; the docs also give the block-rm.sh script):
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "if": "Bash(rm *)",
            "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/block-rm.sh",
            "args": []
          }
        ]
      }
    ]
  }
}
Did it work? Ask Claude to run rm -rf on a test folder. The hook should block it, and it now also checks commands that the Monitor tool starts.
Hooks FIXED · v2.1.314 · OCT 30

Big PreCompact output no longer breaks compaction

Did a chatty hook make Claude fail to shrink a long chat?

Time 5 minLevel beginnerFor plugin authors
What
Compaction is when Claude sums up a long chat to make room. A PreCompact hook runs just before that. Before 2.1.314, a PreCompact hook that printed a lot of text could make compaction fail or repeat. Now each hook's output is cut at 10,000 characters.
Why
Logging and backup hooks can run before compaction without breaking it. Keep what Claude must see under the 10,000 character cap.
Needs
Version 2.1.314 or later.
Save in .claude/settings.json (my example; the PreCompact event and its manual matcher are from the docs):
{
  "hooks": {
    "PreCompact": [
      {
        "matcher": "manual",
        "hooks": [
          {
            "type": "command",
            "command": "echo \"PreCompact ran\" >> ~/precompact.log"
          }
        ]
      }
    ]
  }
}
Did it work? Run /compact, then look in ~/precompact.log for the line PreCompact ran.
Hooks CHANGED · v2.1.312 · OCT 27

Prompt hooks now wait their turn

What happens when your plugins fire lots of AI-checked hooks at once?

Time 10 minLevel intermediateFor plugin authors
What
A hook is a small job that runs at a set moment, like when Claude stops. A prompt hook asks a Claude model to judge that moment and answer yes or no. An agent hook does the same job with a helper that can read files. Since 2.1.312, one session runs at most 24 of these at a time, helpers included. At most 12 more can run once they have waited past their time limit. A timeout under 1 second now counts as 1 second.
Why
A pile of prompt hooks from many plugins can no longer flood your session with model calls.
Needs
Version 2.1.312 for the new limit. The hooks docs name no version for prompt hooks themselves.
Save as hooks/hooks.json in your plugin (the docs' example):
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "prompt",
            "prompt": "Evaluate if Claude should stop: $ARGUMENTS. Check if all tasks are complete."
          }
        ]
      }
    ]
  }
}
Did it work? Run /reload-plugins, then give Claude a small task. Before it stops, the hook checks that the work is done.
Skills FIXED · v2.1.312 · OCT 27

Folder skills keep working after cd

Did a skill go quiet after Claude moved into a deeper folder?

Time 5 minLevel beginnerFor skill authors
What
A skill is a saved set of instructions Claude follows. The paths field tells Claude to load a skill only for files that match a pattern. Before 2.1.312, these skills, and skills kept in a subfolder, were not found after a Bash cd deeper into a git repo. That is fixed.
Why
Skills tied to folders keep showing up in big repos.
Needs
Version 2.1.312. Patterns are read from Claude's current working folder (docs).
Save as .claude/skills/api-style/SKILL.md (my example; the paths field is from the docs):
---
name: api-style
description: Style rules for files in the api folder
paths: "api/**/*.ts"
---

Follow our API style rules when you edit these files.
Did it work? Have Claude cd into a deeper folder, then edit a file under api/. The skill should still load.
Hooks FIXED · v2.1.311 · OCT 26

SubagentStop hooks fire once

Did your clean-up hook run again and again while a helper was still busy?

Time 10 minLevel intermediateFor plugin authors
What
A subagent is a helper Claude starts for one job. A SubagentStop hook runs when that helper finishes. Before 2.1.311, these hooks ran about twice a minute for each helper that was still running. Now they run once, when it finishes.
Why
Clean-up scripts, alerts and logs fire one time per helper, not over and over.
Needs
Version 2.1.311 or later.
In .claude/settings.json, or hooks/hooks.json in a plugin (the docs' example; you write the two scripts):
{
  "hooks": {
    "SubagentStart": [
      {
        "matcher": "db-agent",
        "hooks": [
          { "type": "command", "command": "./scripts/setup-db-connection.sh" }
        ]
      }
    ],
    "SubagentStop": [
      {
        "hooks": [
          { "type": "command", "command": "./scripts/cleanup-db-connection.sh" }
        ]
      }
    ]
  }
}
Did it work? Ask Claude to use a subagent for a small job. The clean-up script should run one time, when the helper is done.

Also new: how I'm using Claude Duet

Anthropic pitches Claude Duet as an agent that keeps working when you stop. It checks your apps, sends a morning brief, and pings you only when something needs you. Most reviews stop at the morning brief. Some testers even say they forgot to use it. I went the other way. I gave it the night shift.

  • It watches my automations, not just my inbox. I run scheduled jobs in Cowork. Duet tells me how each one went. Before, I only found out a job failed when I logged in.
  • It fixed my podcast while I slept. My daily AI news show, AI At The Edge, kept landing about six hours late, and some days I had to start it by hand. Duet sent agents to dig in. They found GitHub was starting my scheduled run hours late. We moved the run to 12:13 AM. The next episode published on its own at 6:19 AM.
  • One text, done by morning. I asked for 10 minute episodes instead of 5. By morning the change was in.
  • It runs this newsletter. A weekly routine reads the changelog, writes these cards and builds the cover. I review it and say go. It also built the workflow that turns this section into an AI video of me.
  • It stays quiet. I keep one channel per subject. Routines post only when something needs me. It drafts my email replies and my weekly church drafts, and I send them myself.

The honest part: it can be slow, and it checks in every few hours, not every minute. That is fine for night shift work.

How to install a plugin

Official store plugins use this form, shown in Anthropic's docs. In a session it opens the plugin's details so you can review it and pick a scope first.

/plugin install commit-commands@claude-plugins-official

To add another store first, run /plugin marketplace add <owner>/<repo>. Then use /plugin install <plugin>@<marketplace>. After you change a plugin, run /reload-plugins.

Stay safe

Plugins run code on your machine. A hook runs every time its moment comes, and prompt and agent hooks send your session's details to a model. Hooks can block a Monitor command but cannot approve it, so keep your deny rules too. Read what a plugin does before you install it.
