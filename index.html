Hooks FIXED · v2.1.309

Make a hook say no

Can a tiny script stop Claude from running a risky command?

Time 10 minLevel intermediateFor team leads
What
A hook is a small program that runs at a set moment, like just before a shell command. If it exits with code 2, the command is blocked and your message goes back to Claude. In 2.1.309, hooks run in PowerShell now block on exit code 2 too. In 2.1.310, Windows hooks no longer let a call through when Git Bash is missing.
Why
One safety rule, enforced the same way on every machine.
Needs
Version 2.1.309 or later for the PowerShell fix. jq for the script below.
.claude/hooks/no-rm.sh (the docs' example; make it executable)
#!/bin/bash
input=$(cat)
command=$(jq -r '.tool_input.command' <<<"$input")

if [[ "$command" == rm* ]]; then
  echo "Blocked: rm commands are not allowed" >&2
  exit 2
fi

exit 0
.claude/settings.json (this wiring is my sketch; check it against the hooks page)
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command", "command": "${CLAUDE_PROJECT_DIR}/.claude/hooks/no-rm.sh" }
        ]
      }
    ]
  }
}
Did it work? Ask Claude to run rm on a throwaway file. It should be refused and show your "Blocked" message.
Skills NEW · v2.1.309

Two skills, same name, no clash

What if your project and a shared folder both have a verify skill?

Time 5 minLevel beginnerFor monorepo teams
What
A skill is a saved set of instructions Claude follows. --add-dir lets a session use another folder. Before 2.1.309, a skill there could not be reached if another skill held its name. Now it gets the folder name as a prefix.
Why
You can use both skills without renaming either one.
Needs
Version 2.1.309 or later. A verify skill in your project and one in ../cli.
In your shell:
claude --add-dir ../cli
Then, in the session:
/verify       # your project's skill
/cli:verify   # the skill from ../cli
Did it work? Type / and look for both verify and cli:verify.
Skills FIXED · v2.1.309

Run a setup step once

Want a skill to check something the first time it runs, and never again?

Time 10 minLevel intermediateFor skill authors
What
A skill can carry its own hooks. Add once: true and Claude Code removes the hook after its first successful run. A failed run keeps it, so it tries again. The 2.1.309 fix: one skill's once hook no longer removes another skill's identical hook.
Why
A one-time check, with no extra noise after it.
Needs
Version 2.1.309 or later. once only works in skill files, not in settings files.
.claude/skills/secure-operations/SKILL.md (the docs' example, with once added)
---
name: secure-operations
description: Perform operations with security checks
hooks:
  PreToolUse:
    - matcher: "Bash"
      hooks:
        - type: command
          command: "./scripts/security-check.sh"
          once: true
---
Did it work? Run the skill and a shell command twice. The check should run on the first one only.
Plugins FROM THE DOCS

Pin the plugins you depend on

What if a plugin you rely on ships a change that breaks yours?

Time 15 minLevel intermediateFor plugin authors
What
A plugin can list other plugins it needs. Add a version range, like ~2.1.0, and users stay on 2.1.x of that dependency. A plugin with only a name and a list works as a team starter pack. To tag a release so ranges can find it, run claude plugin tag --push.
Why
Your plugin does not break the day a dependency changes.
Needs
The docs page names no minimum version. Ranges resolve against git tags named name--vX.Y.Z.
.claude-plugin/plugin.json (the docs' example names)
{
  "name": "deploy-kit",
  "version": "3.1.0",
  "dependencies": [
    "audit-logger",
    { "name": "secrets-vault", "version": "~2.1.0" }
  ]
}
In the dependency's folder, to tag a release:
claude plugin tag --push
Did it work? It prints Created tag and Pushed to origin. Add --dry-run first to see the plan.
Testing FROM THE DOCS · v2.1.269

Give your plugin a report card

How do you know a plugin change did not make things worse?

Time 20 minLevel advancedFor plugin authors
What
claude plugin eval runs sample requests against your plugin and scores the answers. It also runs them without your plugin, so you see what the plugin adds.
Why
You learn if a change made things worse before your users do.
Needs
Version 2.1.269 or later. It uses your model credits, so start small.
In your plugin folder: make a blank test case, then run the suite
claude plugin eval init --bare first-case
claude plugin eval .
To fail a CI job when a score is low:
claude plugin eval . --trust-plugin --json results.json --threshold 0.8
Did it work? You get a table with a score for each case, plus a report.html file.

Also fixed in 2.1.311

  • SubagentStop hooks ran about twice a minute per subagent. They now run once, when it finishes.
  • A skill that runs in a sub-agent no longer runs a second time when a cloud or background session restarts.
  • A --plugin-dir folder of plugins no longer loads as one plugin because of an empty .mcp.json.
  • Subagents can use MCP tools from servers that finish connecting late.

How to install a plugin

Official store plugins use this form, shown in Anthropic's docs:

/plugin install commit-commands@claude-plugins-official

To add another store first, run /plugin marketplace add <owner>/<repo>. Then use /plugin install <plugin>@<marketplace-name>.

Stay safe

Plugins and hooks run code on your machine. Read what they do before you install or enable them.
