Agent SDK ADDED · v2.1.317 · NOV 3

Make a broken safety check fail closed

What if your safety check crashes? Does the risky action still run?

Time 15 minLevel intermediateFor SDK builders
What
A hook is a small check that runs at a set moment, like before Claude runs a command. If an Agent SDK hook callback crashed, the action used to go ahead. Since 2.1.317, you can set onFailure to "block" on the matcher. Then a crash stops the action instead.
Why
A broken guard should fail closed, not open. This matters most for jobs that run with no one watching. Let the error reach the SDK: a callback that catches its own error and returns {} does not count as failing.
Needs
Version 2.1.317. The docs say TypeScript Agent SDK v0.3.317 or later, or Python Agent SDK v0.2.177 or later. Hooks in settings files have had onFailure since v2.1.295 (docs).
In your TypeScript Agent SDK app (the docs' example; checkPolicy is your own check):
import type { Options } from "@anthropic-ai/claude-agent-sdk";

const options: Options = {
  hooks: {
    PreToolUse: [{ matcher: "Bash", hooks: [checkPolicy], onFailure: "block" }]
  }
};
Did it work? Make checkPolicy throw an error, then ask Claude to run a Bash command. The tool result should include: failed; blocking because onFailure is "block".
Plugins FIXED · v2.1.319 · NOV 6

Plugin status lines can find their own scripts

Want your plugin to draw its own row for each helper agent?

Time 15 minLevel intermediateFor plugin authors
What
A subagent is a helper Claude starts for a side job. The agent panel shows one row for each. A plugin can set subagentStatusLine in its settings.json to draw those rows with its own script. ${CLAUDE_PLUGIN_ROOT} stands for the folder where the plugin lives. Before 2.1.319, it was not filled in for this command. Now it is.
Why
You can ship the script inside the plugin, so users do not copy it anywhere. The script reads the rows as JSON and prints one JSON line per row it wants to change (see the docs).
Needs
Version 2.1.319 or later. Only two settings keys work from a plugin: agent and subagentStatusLine (docs).
Save as settings.json at your plugin's root (my example; the shape is from the docs):
{
  "subagentStatusLine": {
    "type": "command",
    "command": "\"${CLAUDE_PLUGIN_ROOT}/scripts/subagent-row.sh\""
  }
}
Did it work? Ask Claude to use a subagent. Its row in the agent panel should show what your script prints.
Hooks CHANGED · v2.1.319 · NOV 6

After-tool hooks still run when you jump in

Does your formatter skip a file when you type mid-task?

Time 5 minLevel beginnerFor plugin authors
What
A PostToolUse hook runs after a tool, like after Claude edits a file. Before 2.1.319, these hooks did not start if you broke into the turn with a new message, and a running hook was stopped. Now, if you send with Ctrl+Enter and the tool finishes, the hooks run on its result. They get up to 10 seconds.
Why
Format and lint hooks no longer miss edits just because you spoke up. Esc still cancels them at once.
Needs
Version 2.1.319 or later. A hook that needs more than 10 seconds can use async: true, but then it cannot block or change the result (docs).
Save as hooks/hooks.json in your plugin (the docs' example):
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "\"${CLAUDE_PLUGIN_ROOT}/scripts/format.sh\""
          }
        ]
      }
    ]
  }
}
Did it work? Ask Claude to edit a file. While it works, type a message and press Ctrl+Enter. The format script should still run on that file.
Plugins FIXED · v2.1.319 · NOV 6

Plugin updates now bring new dependencies

Added a plugin to your team's bundle, but nobody got it?

Time 10 minLevel intermediateFor platform teams
What
A dependency is another plugin that your plugin needs. A bundle is a plugin that mostly lists dependencies, so one install brings a whole set. Before 2.1.319, claude plugin update, the "Update now" button in /plugin, and background auto-update did not install a dependency that a new version added. Now they do.
Why
A team can add a plugin to its bundle, publish a new version, and know people get it on update.
Needs
Version 2.1.319 or later. A version range such as ^3.0 needs the dependency's maintainer to tag releases (docs).
The bundle's .claude-plugin/plugin.json (the docs' example):
{
  "name": "backend-standard",
  "version": "1.0.0",
  "description": "Standard plugin set for backend engineers",
  "dependencies": [
    "secrets-vault",
    "deploy-kit",
    { "name": "db-migrate", "version": "^3.0" },
    "oncall-runbook"
  ]
}
Then in your shell, and run /reload-plugins in an open session (from the docs):
claude plugin update backend-standard
Did it work? Run /plugin and look for the newly added dependency among your installed plugins.
Evals FIXED · v2.1.319 · NOV 6

Test that a tool is never called

How do you prove your plugin did not run a command?

Time 20 minLevel intermediateFor plugin authors
What
claude plugin eval runs your plugin against test cases and scores them. A grader is one pass or fail check. A tool_used grader counts calls to a tool, and its min is 1 unless you set it. Before 2.1.319, eval warnings could suggest max: 0 for a tool that must not be called. With min still at 1, that check could never pass. The bad tip is gone. The docs say to set both min: 0 and max: 0.
Why
"Never do this" checks are how you test a plugin's safety rules.
Needs
Version 2.1.319 for the fix. Git 2.31 or later if git is installed (docs). Eval runs use your plan's usage or your API bill.
Save as evals/first-case/graders/no-bash.md (my example; the fields are from the docs):
---
type: tool_used
tool: Bash
min: 0
max: 0
---
Then from your plugin's root folder (from the docs):
claude plugin eval .
Did it work? The report should show this grader pass on runs where Claude made no Bash call.

How to install a plugin

Official store plugins use this form, shown in Anthropic's docs. In a session it opens the plugin's details so you can review it and pick a scope first.

/plugin install commit-commands@claude-plugins-official

To add another store first, run /plugin marketplace add <owner>/<repo>. Then use /plugin install <plugin>@<marketplace>. After you change a plugin, run /reload-plugins.

Stay safe

Plugins run code on your machine. Hooks and status line scripts run with your own user permissions. onFailure "block" only helps if the error reaches the SDK, so do not hide errors inside a guard. Read what a plugin and its dependencies do before you install them.
