Hooks ADDED · v2.1.328 · NOV 19

Make an MCP hook fail closed

What if the server behind your safety hook goes down?

Time 10 minLevel intermediateFor hook authors
What
A hook is a small check that runs at a set moment, like before a tool runs. An mcp_tool hook asks a tool on an MCP server to do the check. An MCP server is a helper program that gives Claude extra tools. Before 2.1.328, if that server was down or its tool failed, the action went ahead. Now you can set onFailure to block on these hooks too.
Why
A safety check that quietly lets everything through is worse than no check. With block set, a broken check stops the action instead.
Needs
Version 2.1.328 or later for mcp_tool hooks. Command and HTTP hooks have had it since 2.1.295 (docs). Also in 2.1.329: in Code Mode, a PreToolUse hook that errors no longer refuses the call by itself, so set block there too.
Save in .claude/settings.json (my example, built from the docs' mcp_tool example; my_server and security_scan are the docs' sample names):
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "mcp_tool",
            "server": "my_server",
            "tool": "security_scan",
            "input": { "file_path": "${tool_input.file_path}" },
            "onFailure": "block"
          }
        ]
      }
    ]
  }
}
Did it work? Turn the server off in /mcp, then ask Claude to edit a file. The edit should be blocked, not allowed.
Hooks CHANGED · v2.1.330 · NOV 20

Use a short model name in prompt hooks

Want a fast, cheap model to judge your hook?

Time 5 minLevel beginnerFor hook authors
What
A prompt hook asks a model a yes or no question, like "Is the work done?". Its model field picks which model answers. Since 2.1.330, that field takes short names such as haiku or sonnet, not just full model IDs.
Why
A short name is easier to read and to share. You don't have to update a long ID each time a new model comes out.
Needs
Version 2.1.330 or later. Without a model, the hook uses the model Claude Code picks for background work (docs).
Save in .claude/settings.json (the docs' Stop prompt hook; the model line is my addition):
{
  "hooks": {
    "Stop": [
      {
        "hooks": [
          {
            "type": "prompt",
            "prompt": "Check if all tasks are complete. If not, respond with {\"ok\": false, \"reason\": \"what remains to be done\"}.",
            "model": "haiku"
          }
        ]
      }
    ]
  }
}
Did it work? Ask Claude for a small task. When it stops, the hook should check the work, and Claude keeps going if something is left.
Status ADDED · v2.1.327 · NOV 17

Find hooks that never fire

Is one of your hooks watching for a tool name that doesn't exist?

Time 2 minLevel beginnerFor anyone with hooks or plugins
What
A matcher tells a hook which tools to watch. One typo and the hook never runs, with no error. Since 2.1.327, /status lists hook matchers that never match. It also lists broken agent, skill, command and output style files, an unavailable sandbox, ignored permission settings and keybinding errors.
Why
A check that never runs gives you a false sense of safety. Now one command shows it.
Needs
Version 2.1.327 or later.
In a Claude Code session:
/status
Did it work? If something is wrong, /status names it. Fix the matcher or file, then run /status again.
Install ADDED · v2.1.330 · NOV 20

See when a plugin's install command fails

Does your setup script know when a plugin install half worked?

Time 10 minLevel intermediateFor platform teams
What
Some marketplaces run a command to install a plugin. With --json, claude plugin install prints one JSON object on the last line. Since 2.1.330 it has two new fields. commandPrinted is true when the install worked but the command wrote to stderr, the error stream. commandFailed is true when the command exited with an error, was killed or timed out.
Why
A script can now tell a clean install from a noisy one or a failed one, without reading the screen.
Needs
Version 2.1.330 for the two fields. --json needs 2.1.268 or later. Parse only the last line of output (docs).
In your shell or setup script (my example; formatter@my-marketplace is the docs' sample plugin):
claude plugin install formatter@my-marketplace --json
Did it work? Read the last line. Look for outcome, then commandPrinted or commandFailed when the source runs a command.
Evals CHANGED · v2.1.327 · NOV 17

Evals keep their limits over a plugin's hook

Could a plugin's own hook sneak past your test limits?

Time 10 minLevel intermediateFor plugin authors
What
claude plugin eval runs your plugin against test cases and scores the results. A run only allows the tools you grant. A permission hook can answer allow or deny for a tool call. Since 2.1.327, the eval's deny rules win over a plugin's permission hook. The report also flags calls the hook let through.
Why
Your scores now come from the limits you set, not from what the plugin allowed itself.
Needs
Version 2.1.327 or later. A Bash grant runs under the sandbox. Only evaluate plugins you trust (docs).
In your shell, from the plugin folder (from the docs):
claude plugin eval . --allow-tools Write Edit "Bash(npm test *)"
Did it work? Look in the report for any call the plugin's hook let through. A flagged call is one to review.

Also this week

  • 2.1.326: a hook's "decision": "block" now holds in more cases. A hook that always prints one may start blocking calls, so check yours.
  • 2.1.326: enabled plugins that were refused for a bad plugin.json display field, such as author, now load with their hooks and MCP servers. /plugin and claude plugin list note the ignored field. Admins should check the plugins they deploy.
  • 2.1.326: uninstalling a plugin also deletes the files unpacked from its MCP bundles (.mcpb, .dxt), unless another plugin uses them.
  • 2.1.326: /plugin uninstall, remove and switch questions now use the arrow keys and Enter. y, n and u no longer answer them.
  • 2.1.326: plugin and marketplace requests now fail after 25 seconds when ALL_PROXY is the only proxy and it never answers.
  • 2.1.326: hook failures show in red and blocks in yellow, with the reason under them. A PreToolUse hook that exits 127 now says its check may not have run.
  • 2.1.327: a plugin's agent is no longer dropped when you resume from the --resume picker, and --agents survive a plugin reload. Restarted background subagents wait for plugins to load.
  • 2.1.327: removing a marketplace now warns that its plugins' settings and saved data are deleted. Failing SubagentStop, SessionEnd, CwdChanged and FileChanged hooks now show an error.
  • 2.1.328: managed PostToolUse hooks no longer fire for calls refused before they ran. Apps that embed Claude Code can switch on the policy plugin's allowManagedModsOnly option.
  • 2.1.328: fixes in /plugin: holding Enter no longer turns off several plugins, and it no longer asks to uninstall the wrong one. A plugin's toast no longer shows another plugin's text.
  • 2.1.329: the trust dialog now says where a folder's hooks are declared. /status has a "Marketplace auto-update" row naming managed marketplaces that don't auto-update, and why.
  • 2.1.329: cloud sessions retry plugins that failed to download at startup. A removed plugin's MCP server no longer stays connected in headless sessions.
  • 2.1.330: plugins no longer go missing from the installed list when several claude plugin commands run at once. /mcp now lists plugin servers under "Plugin MCPs".
  • 2.1.330: a plugin with errors now shows them first in /plugin. Cloud sessions show a notice when a plugin marketplace's repository isn't one of the session's.
  • 2.1.330: environment variables written by a SessionStart hook are kept with claude -p --continue. claude plugin validate no longer wrongly warns about a mod's AbovePrompt hook in VS Code.

How to install a plugin

Official store plugins use this form, shown in Anthropic's docs. In a session it opens the plugin's details so you can review it and pick a scope first.

/plugin install commit-commands@claude-plugins-official

To add another store first, run /plugin marketplace add <owner>/<repo>. Then use /plugin install <plugin>@<marketplace>. After you change a plugin, run /reload-plugins.

Stay safe

Plugins run code on your computer, with access to your files and shell. Hooks run with your own user permissions. A safety hook should fail closed: set onFailure to block. Only evaluate or install plugins you trust.
