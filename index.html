Skills CHANGED · v2.1.325 · NOV 13

Let a scheduled task run your skill

Did your /loop job stop and wait for you at 2 AM?

Time 10 minLevel beginnerFor anyone who schedules work
What
A skill is a saved set of instructions Claude follows. Some skills list allowed-tools, which are tools they may use without asking. Some carry hooks, which are small checks. Since 2.1.325, scheduled tasks and /loop ask you first before they run a skill like that. To let one run on its own, add Skill(name) to permissions.allow.
Why
A skill with its own tool grants is strong. Now it can't run with no one watching unless you named it. One rule per skill keeps that choice clear.
Needs
Version 2.1.325 or later. Skill(name) matches one skill. Skill(name *) matches it with any arguments (docs).
Save in .claude/settings.json (my example; the rule form is from the docs; commit stands for your skill's name):
{
  "permissions": {
    "allow": [
      "Skill(commit)"
    ]
  }
}
Did it work? Start a loop that runs the skill, such as /loop 20m /commit. The next run should start the skill without a question.
Mods CHANGED · v2.1.321 · NOV 9

Mods now reload in headless runs

Fixed your mod mid-run, but the script kept the old one?

Time 5 minLevel intermediateFor plugin authors
What
A mod is a plugin part that changes Claude Code itself, like a pane or a rule for tool calls. A headless run has no chat window, like claude -p. Since 2.1.321, headless sessions reload mods in .claude/skills when their files change. Set CLAUDE_CODE_PLUGIN_DIR_WATCH to 0 to turn reloading off everywhere.
Why
Long scripted runs pick up your fixes right away. If a run must stay the same from start to end, turn reloading off for that run.
Needs
Version 2.1.321 for the headless change. The variable itself needs v2.1.287 or later. By the docs, mods in --plugin-dir folders reload only in interactive terminal sessions unless you set it to 1.
In your shell (my example):
CLAUDE_CODE_PLUGIN_DIR_WATCH=0 claude -p "summarize this repo"
Did it work? Change a mod's file while the run is going. With 0 set, the run keeps the version it started with.
Hooks CHANGED · v2.1.323 · NOV 12

A hook's yes no longer covers a broken check

What happens when your hook says yes, but the safety check breaks?

Time 10 minLevel intermediateFor hook authors
What
A PreToolUse hook runs before a tool. It can answer "allow" to skip the prompt. Claude Code then still runs its own permission check on the call. Since 2.1.323, if that check fails with an error, Claude Code decides the call as if no hook had answered. If a PermissionRequest hook rewrote the input and the check fails, it asks again, or refuses where nobody can answer.
Why
A hook's yes only counts when the check behind it works. A crash now falls back to the normal rules, not a free pass.
Needs
Version 2.1.323 or later. Deny and ask rules still apply, whatever a hook returns (docs).
What your hook prints (my example, using fields from the docs):
{
  "hookSpecificOutput": {
    "hookEventName": "PreToolUse",
    "permissionDecision": "allow",
    "permissionDecisionReason": "My reason here"
  }
}
Did it work? Normal calls skip the prompt. If the permission check errors, you get the usual prompt or rule result instead.
Marketplaces CHANGED · v2.1.325 · NOV 13

Pin a plugin store to one commit

Reviewed your team's plugin store, then someone pushed a change?

Time 15 minLevel intermediateFor platform teams
What
A marketplace is a store that lists plugins. Its ref picks which version of its git repo to use. A commit SHA is the long ID of one exact change. The 2.1.325 notes say ref now takes the full SHA of any commit on a branch or tag.
Why
Refreshes and auto-updates can't move you off a commit you checked. That gives a team one known set of plugins.
Needs
The docs say v2.1.324 or later. Update Claude Code on every machine first, because older versions can't load a store pinned this way. Reserved names such as claude-plugins-official can't use a SHA. A plugin entry with its own remote source can still update, so pin it too with sha (docs).
The marketplace source (the docs' example; use your repo and your commit's SHA):
{ "source": "github", "repo": "acme-corp/plugins", "ref": "a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0" }
Did it work? Push a new commit to the store's repo. After a refresh, your plugins should stay on the pinned commit.
Validate ADDED · v2.1.323 · NOV 12

Catch mod type errors before you ship

Want CI to stop a broken mod before your team installs it?

Time 5 minLevel beginnerFor plugin authors
What
claude plugin validate checks a plugin's files. Since 2.1.323, it also type checks a plugin's TypeScript hooks module, the code behind a mod. Each finding is a warning. With --strict, a warning fails the run. Since 2.1.325, it also reports some unsafe paths and links in a plugin's folder, which loading now skips.
Why
A type error found in CI costs minutes. Found on a teammate's laptop, it costs a lot more.
Needs
Version 2.1.323 for type checks and 2.1.325 for the path checks. --strict treats warnings as errors (docs).
In your shell or CI job (from the docs):
claude plugin validate ./my-plugin --strict
Did it work? Exit code 0 means it passed. Exit code 1 prints "Validation failed (--strict treats warnings as errors)" when a warning stopped it.

Special Edition: Claude joined the meeting

This week I made a short video about AI in meetings. Here is the short version.

A transcript gives you accurate minutes. You can search for what was decided. Every action item gets an owner.

For engineers, this matters a lot. Many design and architecture choices are made in meetings. That was always useful, but it was often lost when no one took notes. Now AI turns a transcript into minutes in seconds. That even works for older meetings, if you kept the recording or transcript.

Minutes are the context a large language model (LLM) needs: what we decided, why, and what we ruled out. Give them to Claude next to the code. It drafts the plan to build it. You review it and approve it.

Claude Meetings is now in beta for Team and Enterprise plans. Claude joins a Google Meet call as a visible participant.

Large regulated companies often lock down transcription. Reasons include consent laws, lawsuits against AI note takers, records rules and legal privilege. This is for your information only, not legal advice.

A bigger answer is to run Claude Managed Agents inside your own security perimeter. Anthropic offers this as a private beta.

Start small. Pick one internal meeting type. Tell everyone first. Have a person approve the notes.

How to install a plugin

Official store plugins use this form, shown in Anthropic's docs. In a session it opens the plugin's details so you can review it and pick a scope first.

/plugin install commit-commands@claude-plugins-official

To add another store first, run /plugin marketplace add <owner>/<repo>. Then use /plugin install <plugin>@<marketplace>. After you change a plugin, run /reload-plugins.

Stay safe

Plugins run code on your computer, with access to your files and shell. Hooks and mods run with your own user permissions. Only allow a skill by name if you know what it does. Pin a store only to a commit you have read.
